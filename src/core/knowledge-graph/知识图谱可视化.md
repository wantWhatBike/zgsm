## 技术约束与选型
1.  **渲染引擎**：d3.js (v7+) + **HTML5 Canvas**。
    *   **决策**：为了实现 10 万级节点的流畅渲染和炫酷的光影效果，必须使用 Canvas。SVG 无法承载大量节点的发光和粒子特效。
2.  **计算架构**：**Web Worker**。
    *   **决策**：**这是防卡死的底线**。考虑到用户环境（8C 16G Windows 虚拟机），力导向布局计算（CPU 密集型）必须在 Web Worker 中运行，避免阻塞 UI 主线程。
3.  **数据策略**：**全量加载 + 前端过滤**。
    *   **决策**：10 万节点的基础数据（ID、类型、关系）压缩后约 2-5MB，完全可以一次性传输到前端。前端 Worker 负责根据当前的“展开/折叠”状态过滤参与布局的节点，避免频繁的后端通信延迟。
4.  **运行环境**：VSCode Webview Panel (全屏)。
5.  **布局**：力导向布局 (Force-Directed Layout)。

D3 in React
Most D3 modules (including d3-scale, d3-array, d3-interpolate, and d3-format) don’t interact with the DOM, so there is no difference when using them in React. You can use them in JSX for purely declarative visualization, such as the line plot below.
Most D3 modules (including d3-scale, d3-array, d3-interpolate, and d3-format) don’t interact with the DOM, so there is no difference when using them in React. You can use them in JSX for purely declarative visualization, such as the line plot below.
```jsx
import * as d3 from "d3";

export default function LinePlot({
  data,
  width = 640,
  height = 400,
  marginTop = 20,
  marginRight = 20,
  marginBottom = 20,
  marginLeft = 20
}) {
  const x = d3.scaleLinear([0, data.length - 1], [marginLeft, width - marginRight]);
  const y = d3.scaleLinear(d3.extent(data), [height - marginBottom, marginTop]);
  const line = d3.line((d, i) => x(i), y);
  return (
    <svg width={width} height={height}>
      <path fill="none" stroke="currentColor" strokeWidth="1.5" d={line(data)} />
      <g fill="white" stroke="currentColor" strokeWidth="1.5">
        {data.map((d, i) => (<circle key={i} cx={x(i)} cy={y(d)} r="2.5" />))}
      </g>
    </svg>
  );
}
```
D3 modules that operate on selections (including d3-selection, d3-transition, and d3-axis) do manipulate the DOM, which competes with React’s virtual DOM. In those cases, you can attach a ref to an element and pass it to D3 in a useEffect hook.
```jsx
import * as d3 from "d3";
import {useRef, useEffect} from "react";

export default function LinePlot({
  data,
  width = 640,
  height = 400,
  marginTop = 20,
  marginRight = 20,
  marginBottom = 30,
  marginLeft = 40
}) {
  const gx = useRef();
  const gy = useRef();
  const x = d3.scaleLinear([0, data.length - 1], [marginLeft, width - marginRight]);
  const y = d3.scaleLinear(d3.extent(data), [height - marginBottom, marginTop]);
  const line = d3.line((d, i) => x(i), y);
  useEffect(() => void d3.select(gx.current).call(d3.axisBottom(x)), [gx, x]);
  useEffect(() => void d3.select(gy.current).call(d3.axisLeft(y)), [gy, y]);
  return (
    <svg width={width} height={height}>
      <g ref={gx} transform={`translate(0,${height - marginBottom})`} />
      <g ref={gy} transform={`translate(${marginLeft},0)`} />
      <path fill="none" stroke="currentColor" strokeWidth="1.5" d={line(data)} />
      <g fill="white" stroke="currentColor" strokeWidth="1.5">
        {data.map((d, i) => (<circle key={i} cx={x(i)} cy={y(d)} r="2.5" />))}
      </g>
    </svg>
  );
}
```
For more guidance using D3 in React, see Amelia Wattenberger’s post[https://2019.wattenberger.com/blog/react-and-d3].


## 详细设计

### 1. 视觉风格设计 (Visual Style) - 性能优先的炫酷
目标是打造一个**深色、科技感、星系状**的知识图谱。

*   **主题色 (Theme)**：**深色宇宙 (Dark Cosmos)**。背景使用深灰/黑色 (`#1e1e1e` 或更深)，避免刺眼，突显节点亮度。
*   **节点渲染 (Nodes)**：
    *   **发光效果 (Glow)**：**[性能修正]** 严禁在渲染循环中使用 `ctx.shadowBlur`。
        *   **方案**：使用 **预渲染 Sprite (贴图)**。在内存 Canvas 中预先画好几种不同颜色/大小的“发光圆点”，渲染时直接使用 `drawImage` 复用这些贴图。
    *   **颜色编码**：
        *   **目录**：紫色/深蓝，代表“星系中心”。
        *   **Source文件**：青色 (Cyan)，代表逻辑。
        *   **Test文件**：绿色 (Green)，代表保障。
        *   **Config文件**：橙色 (Orange)，代表配置。
    *   **大小映射**：
        *   目录：固定较大半径，或根据包含文件数对数增长。
        *   文件：根据文件大小或 PageRank 值动态调整。
*   **连线渲染 (Links)**：
    *   **基础状态**：低透明度 (0.1-0.2) 的细线。
    *   **高亮状态**：高亮且发光，模拟“能量传输”。

### 2. 交互与动效设计 (Interaction & Animation)

#### 2.1 动态交互
*   **入场策略 (Loading Strategy)**：
    *   **默认折叠**：初始只展示 **Root 目录** 和 **一级子目录/文件**。
    *   **渐进式展开**：双击目录节点，展开/折叠其直接子节点。
    *   **布局更新**：展开时，新节点从父节点位置“生出”，力导向重新平衡；折叠时，子节点收缩回父节点。
*   **悬浮 (Hover) - 聚光灯效果**：
    *   鼠标悬浮节点时，**高亮**该节点及其直接依赖路径（上游和下游）。
    *   **压暗 (Dim)** 其他无关节点。
*   **点击 (Click) - 详情与定位**：
    *   点击节点：右侧滑出详情面板。
    *   双击文件节点：在 VSCode 编辑器中打开该文件。

#### 2.2 基础操作
*   **缩放/平移**：支持鼠标滚轮缩放和拖拽平移。
*   **搜索定位**：提供搜索框，输入文件名，视图自动飞向并高亮目标节点。

### 3. 性能优化方案 (Performance Optimization)

#### 3.1 计算优化 (Web Worker)
*   **独立线程**：`GraphWorker.ts` 负责 d3-force 的 simulation tick 计算。
*   **消息机制**：
    *   Main -> Worker: 发送全量 GraphData，或发送“展开/折叠”指令（更新 nodes/links 子集）。
    *   Worker -> Main: 每帧（或每N帧）发送计算后的节点坐标 `Float32Array`。

#### 3.2 渲染优化 (Rendering)
*   **离屏 Canvas**：静态背景、网格绘制在离屏 Canvas。
*   **视锥剔除 (Frustum Culling)**：只渲染 Viewport 内的节点。
*   **LOD (Level of Detail)**：
    *   Zoom < 0.5: 隐藏文字标签，只画点。
    *   Zoom < 0.2: 隐藏连线，只画大目录点。

#### 4.2 图谱数据结构 (GraphData)
保持 Schema 简洁，减少传输体积。

```typescript
export interface GraphNode {
  id: string;       // 路径 (唯一标识)
  label: string;    // 文件名/目录名
  type: 'file' | 'directory';
  fileType?: 'source' | 'config' | 'test'; // 仅文件节点有
  size: number;     // 文件大小 (字节)
  parentId?: string; // 父目录路径，用于构建树形结构
  // 附加信息 (可选，用于详情展示，可按需异步加载，这里先包含)
  description?: string;
}

export interface GraphLink {
  source: string; // 源节点 ID
  target: string; // 目标节点 ID
  type: 'import' | 'reference' | 'contains'; // 关系类型
}

export interface GraphData {
  nodes: GraphNode[];
  links: GraphLink[];
}
```

### 5. 后端实现逻辑 (`src/core/knowledge-graph`)

#### 5.1 `GraphRetriever.ts`
*   **新增方法**：`getGraphData(workspacePath: string): Promise<GraphData>`
*   **核心逻辑**：
    1.  **获取摘要**：调用 `FileSummarizer` 和 `DirectorySummarizer` 获取所有已分析的摘要。
    2.  **构建节点**：
        *   将所有 `DirectorySummary` 转换为 `GraphNode` (type='directory')。
        *   将所有 `FileSummary` 转换为 `GraphNode` (type='file')。
    3.  **构建边**：
        *   **Contains**: 根据文件/目录路径层级，生成父子包含关系边。
        *   **Import**: 解析 `FileSummary.dependencies`，生成文件依赖边。
    4.  **返回**：返回全量 `GraphData`。

#### 5.2 `KnowledgeGraphMessageHandler.ts`
*   **处理 `OPEN_GRAPH_VIEW`**：创建 Webview Panel。
*   **处理 `GET_GRAPH_DATA`**：调用 `GraphRetriever` 并返回数据。
*   **处理 `OPEN_FILE`**：调用 `vscode.window.showTextDocument`。

### 6. 前端实现逻辑 (`webview-ui`)

#### 6.1 `GraphVisualizer.tsx` (容器)
*   管理 Webview 消息通信。
*   管理 `GraphData` 状态。
*   实例化 `GraphWorker`。

#### 6.2 `GraphWorker.ts`
*   引入 `d3-force`。
*   接收主线程传来的 `nodes` 和 `links`。
*   维护一个 `simulation` 实例。
*   监听 `tick` 事件，通过 `postMessage` 发送位置数据。
*   处理“过滤”逻辑：根据前端传入的 `expandedDirectories` Set，筛选出当前应该参与布局的节点和边，重启 simulation。

#### 6.3 `ForceGraph.tsx`
*   接收 Worker 传回的坐标数据。
*   使用 `requestAnimationFrame` 执行 Canvas 绘制。
*   处理鼠标事件（Hover, Click, Drag, Zoom），将坐标转换为逻辑坐标后处理。
