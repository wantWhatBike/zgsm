## 需求背景
当前已经有了知识图谱的存储、构建功能，现在需要增加知识图谱的可视化功能，以便用户直观地理解项目结构和文件依赖关系。

- **前端代码**：`@/webview-ui/src/components/settings/ZgsmKnowledgeGraphSettings.tsx` (入口)
- **后端代码**：`@/src/core/knowledge-graph`

## 技术约束与选型
1.  **渲染引擎**：d3.js (v7+) + **HTML5 Canvas**。
    *   **决策**：为了实现 10 万级节点的流畅渲染和炫酷的光影效果，必须使用 Canvas。SVG 无法承载大量节点的发光和粒子特效。
2.  **计算架构**：**Web Worker**。
    *   **决策**：**这是防卡死的底线**。考虑到用户环境（8C 16G Windows 虚拟机），力导向布局计算（CPU 密集型）必须在 Web Worker 中运行，避免阻塞 UI 主线程。
3.  **运行环境**：VSCode Webview Panel (全屏)。
4.  **布局**：力导向布局 (Force-Directed Layout)。

## 详细设计

### 1. 视觉风格设计 (Visual Style) - 牛逼优先
目标是打造一个**深色、科技感、星系状**的知识图谱，提供“上帝视角”的震撼体验。

*   **主题色 (Theme)**：**深色宇宙 (Dark Cosmos)**。背景使用深灰/黑色 (`#1e1e1e` 或更深)，避免刺眼，突显节点亮度。
*   **节点渲染 (Nodes)**：
    *   **发光效果 (Glow)**：利用 Canvas 的 `shadowBlur` 和 `shadowColor`，让核心节点（目录、重要文件）产生外发光效果，像星星一样。
    *   **颜色编码**：
        *   **目录**：根据层级使用不同饱和度的紫色/蓝色，代表“星系中心”。
        *   **Source文件**：青色/蓝色 (Cyan/Blue)，代表逻辑。
        *   **Test文件**：绿色 (Green)，代表保障。
        *   **Config文件**：黄色/橙色 (Yellow/Orange)，代表配置。
    *   **大小映射**：根据文件大小或被引用次数（PageRank，前端计算）动态调整节点半径。
*   **连线渲染 (Links)**：
    *   **基础状态**：低透明度的细线，避免视觉杂乱。
    *   **高亮状态**：高亮且发光，模拟“能量传输”。

### 2. 交互与动效设计 (Interaction & Animation)

#### 2.1 动态交互
*   **入场动画 (Big Bang)**：
    *   **全量加载**：不再默认折叠，而是展示全貌。
    *   **生长动效**：图谱加载时，节点从中心向外爆发式展开，或者按目录层级逐级“生长”出来。这既是视觉特效，也能分散渲染压力。
*   **悬浮 (Hover) - 聚光灯效果**：
    *   鼠标悬浮节点时，**高亮**该节点及其直接依赖路径（上游和下游）。
    *   **压暗 (Dim)** 其他无关节点，聚焦用户视线。
    *   **粒子流动**：在关联的边上增加粒子流动动画，指示依赖方向。
*   **点击 (Click) - 镜头飞行**：
    *   点击节点时，画布视图**平滑飞行 (Fly To)** 并缩放到该节点居中，而不是生硬跳转。
    *   右侧滑出详情面板。

#### 2.2 基础操作
*   **缩放/平移**：流畅的鼠标滚轮缩放和拖拽平移。
*   **节点拖拽**：拖拽节点时有弹性反馈，释放后自然回弹。
*   **目录折叠/展开**：虽然默认全展开，但仍提供手动折叠功能，方便用户聚焦局部。

### 3. 性能优化方案 (Performance Optimization) - 兼顾流畅
在追求视觉效果的同时，通过技术手段保障基本流畅度，防止系统卡死。

#### 3.1 计算优化 (Web Worker)
*   **独立线程**：将 d3-force 的 simulation 逻辑完全移至 `GraphWorker.ts`。
*   **数据传输**：使用 `Transferable Objects` (如 Float32Array) 在主线程和 Worker 之间传输节点位置数据。
*   **效果**：无论后台计算多复杂，主线程 UI 始终响应鼠标操作，**绝不卡死**。

#### 3.2 渲染优化 (Rendering) - 动态降级
*   **动态 LOD (Dynamic Level of Detail)**：
    *   **静止状态**：开启全特效（发光、抗锯齿、高精度文字），享受视觉盛宴。
    *   **交互状态**（拖拽/缩放）：**自动降级**。关闭发光、隐藏文字、减少连线透明度，只渲染基础点线，确保帧率稳定。
*   **视锥剔除 (Frustum Culling)**：只渲染当前视口（Viewport）可见范围内的节点和边。
*   **分层渲染**：
    *   **静态层**：背景网格。
    *   **动态层**：节点、边（随布局更新）。
    *   **交互层**：高亮、Tooltip（独立 Canvas，高频重绘）。

### 4. 数据接口定义

#### 4.1 消息类型
```typescript

type WebviewMessage = 
  | { type: 'OPEN_KNOWLEDGE_GRAPH' }
  | { type: 'GET_GRAPH_DATA' }
  | { type: 'GET_NODE_DETAILS', payload: { path: string } }
  | { type: 'OPEN_FILE', payload: { path: string } };

// 发送给前端
type ExtensionMessage = 
  | { type: 'GRAPH_DATA_RESPONSE', payload: GraphData }
  | { type: 'NODE_DETAILS_RESPONSE', payload: NodeDetails };
```

#### 4.2 图谱数据结构 (GraphData)
保持 Schema 简洁，视觉属性由前端根据数据计算。

```typescript
interface GraphData {
  nodes: GraphNode[];
  links: GraphLink[];
}

interface GraphNode {
  id: string;       // 路径
  label: string;    // 文件名/目录名
  type: 'file' | 'directory';
  fileType?: 'source' | 'config' | 'test'; // 用于颜色
  size: number;     // 用于基础大小
  group?: string;   // 父目录，用于聚类
  // 前端计算属性：
  // importance: number (根据引用数计算，影响发光强度)
  // x, y, vx, vy (d3-force 计算)
}

interface GraphLink {
  source: string;
  target: string;
  type: 'import' | 'reference' | 'contains';
}
```

#### 4.3 节点详情结构 (NodeDetails)
```typescript
interface NodeDetails {
  path: string;
  type: 'file' | 'directory';
  description: string; // 详细描述
  summary?: string;    // 一句话摘要（可选，若无则截取description）
  keywords: string[];
  functions?: Record<string, string>;
  lastModified?: number;
}
```

### 5. 后端实现逻辑 (`src/core/knowledge-graph`)

#### 5.1 `GraphRetriever.ts`
*   **核心逻辑**：
    1.  读取所有 `FileSummary` 和 `DirectorySummary`。
    2.  构建节点：目录节点 + 文件节点。
    3.  构建边：
        *   `contains`: 父目录 -> 子文件/子目录 (构建骨架)。
        *   `import`: 文件 -> 依赖文件 (构建关联)。
    4.  **无需复杂计算**：后端只负责吐出原始拓扑结构，复杂的视觉计算（如 PageRank、颜色映射）交给前端，利用客户端算力。

### 6. 前端实现逻辑 (`webview-ui`)

#### 6.1 `ForceGraph.tsx` (渲染核心)
*   **Canvas 绘图循环**：
    *   `ctx.globalCompositeOperation = 'lighter'` (叠加模式，实现发光效果)。
    *   **绘制边**：先画暗淡的背景线，再画高亮的交互线。
    *   **绘制节点**：
        *   `ctx.shadowBlur = node.importance * 10` (根据重要性发光)。
        *   `ctx.fillStyle` 根据 `fileType` 填充霓虹色。
        *   `ctx.arc()` 绘制圆形。
*   **力导向配置**：
    *   `d3.forceManyBody().strength(-300)`: 强排斥力，防止重叠。
    *   `d3.forceLink().distance(link => link.type === 'contains' ? 50 : 100)`: 目录包含关系紧凑，依赖关系疏松。
    *   `d3.forceCluster()`: 自定义聚类力，让同目录节点抱团。

#### 6.2 详情展示
*   **Tooltip**：鼠标 Hover 时显示，半透明磨砂玻璃效果 (Backdrop Filter)，只显示文件名和类型。
*   **Side Panel**：点击后右侧滑出。
    *   **Header**：大号文件名，配大图标。
    *   **Content**：结构化展示描述、函数列表（带跳转图标）、依赖列表。
    *   **Style**：保持与 VSCode 主题一致的深色风格，精致的排版。
