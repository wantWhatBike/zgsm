## 技术约束与选型
1.  **渲染引擎**：d3.js (v7+) + **HTML5 Canvas**。
    *   **决策**：为了实现 10 万级节点的流畅渲染和炫酷的光影效果，必须使用 Canvas。SVG 无法承载大量节点的发光和粒子特效。
2.  **计算架构**：**Web Worker**。
    *   **决策**：**这是防卡死的底线**。考虑到用户环境（8C 16G Windows 虚拟机），力导向布局计算（CPU 密集型）必须在 Web Worker 中运行，避免阻塞 UI 主线程。
3.  **数据策略**：**全量加载 + 前端过滤**。
    *   **决策**：10 万节点的基础数据（ID、类型、关系）压缩后约 2-5MB，完全可以一次性传输到前端。前端 Worker 负责根据当前的“展开/折叠”状态过滤参与布局的节点，避免频繁的后端通信延迟。
4.  **运行环境**：VSCode Webview Panel (全屏)。
5.  **布局**：力导向布局 (Force-Directed Layout)。

```jsx
import * as d3 from "d3";

export default function LinePlot({
  data,
  width = 640,
  height = 400,
  marginTop = 20,
  marginRight = 20,
  marginBottom = 20,
  marginLeft = 20
}) {
  const x = d3.scaleLinear([0, data.length - 1], [marginLeft, width - marginRight]);
  const y = d3.scaleLinear(d3.extent(data), [height - marginBottom, marginTop]);
  const line = d3.line((d, i) => x(i), y);
  return (
    <svg width={width} height={height}>
      <path fill="none" stroke="currentColor" strokeWidth="1.5" d={line(data)} />
      <g fill="white" stroke="currentColor" strokeWidth="1.5">
        {data.map((d, i) => (<circle key={i} cx={x(i)} cy={y(d)} r="2.5" />))}
      </g>
    </svg>
  );
}
```

D3 modules that operate on selections (including d3-selection, d3-transition, and d3-axis) do manipulate the DOM, which competes with React’s virtual DOM. In those cases, you can attach a ref to an element and pass it to D3 in a useEffect hook.
```jsx
import * as d3 from "d3";
import {useRef, useEffect} from "react";

export default function LinePlot({
  data,
  width = 640,
  height = 400,
  marginTop = 20,
  marginRight = 20,
  marginBottom = 30,
  marginLeft = 40
}) {
  const gx = useRef();
  const gy = useRef();
  const x = d3.scaleLinear([0, data.length - 1], [marginLeft, width - marginRight]);
  const y = d3.scaleLinear(d3.extent(data), [height - marginBottom, marginTop]);
  const line = d3.line((d, i) => x(i), y);
  useEffect(() => void d3.select(gx.current).call(d3.axisBottom(x)), [gx, x]);
  useEffect(() => void d3.select(gy.current).call(d3.axisLeft(y)), [gy, y]);
  return (
    <svg width={width} height={height}>
      <g ref={gx} transform={`translate(0,${height - marginBottom})`} />
      <g ref={gy} transform={`translate(${marginLeft},0)`} />
      <path fill="none" stroke="currentColor" strokeWidth="1.5" d={line(data)} />
      <g fill="white" stroke="currentColor" strokeWidth="1.5">
        {data.map((d, i) => (<circle key={i} cx={x(i)} cy={y(d)} r="2.5" />))}
      </g>
    </svg>
  );
}
```

```js
  // Specify the dimensions of the chart.

  const height = 680;

  // Specify the color scale.
  const color = d3.scaleOrdinal(d3.schemeCategory10);

  const links = data.links.map(d => ({...d}));

      .force("x", d3.forceX())
      .force("y", d3.forceY());

      .attr("height", height)
      .attr("viewBox", [-width / 2, -height / 2, width, height])

    .data(links)

      .attr("stroke", "#fff")

    .selectAll("circle")
    .data(nodes)
    .join("circle")
      .attr("r", 5)
      .attr("fill", d => color(d.group));

  node.append("title")
      .text(d => d.id);

  // Add a drag behavior.
  node.call(d3.drag()
        .on("start", dragstarted)
        .on("drag", dragged)
        .on("end", dragended));
  
  // Set the position attributes of links and nodes each time the simulation ticks.
  simulation.on("tick", () => {
    link
        .attr("x1", d => d.source.x)
        .attr("y1", d => d.source.y)
        .attr("x2", d => d.target.x)
        .attr("y2", d => d.target.y);

    node
        .attr("cx", d => d.x)
        .attr("cy", d => d.y);
  });

  // Reheat the simulation when drag starts, and fix the subject position.
  function dragstarted(event) {
    if (!event.active) simulation.alphaTarget(0.3).restart();
    event.subject.fx = event.subject.x;
    event.subject.fy = event.subject.y;
  }

  // Update the subject (dragged node) position during drag.
  function dragged(event) {
    event.subject.fx = event.x;
    event.subject.fy = event.y;
  }

  // Restore the target alpha so the simulation cools after dragging ends.
  // Unfix the subject position now that it’s no longer being dragged.
  function dragended(event) {
    if (!event.active) simulation.alphaTarget(0);
    event.subject.fx = null;
    event.subject.fy = null;
  }

  // When this cell is re-run, stop the previous simulation. (This doesn’t
  // really matter since the target alpha is zero and the simulation will
  // stop naturally, but it’s a good practice.)
  invalidation.then(() => simulation.stop());

  return svg.node();
```

**Force-directed graph component**
```js
function ForceGraph({
  nodes, // an iterable of node objects (typically [{id}, …])
  links // an iterable of link objects (typically [{source, target}, …])
}, {
  nodeId = d => d.id, // given d in nodes, returns a unique identifier (string)
  nodeGroup, // given d in nodes, returns an (ordinal) value for color
  nodeGroups, // an array of ordinal values representing the node groups
  nodeTitle, // given d in nodes, a title string
  nodeFill = "currentColor", // node stroke fill (if not using a group color encoding)
  nodeStroke = "#fff", // node stroke color
  nodeStrokeWidth = 1.5, // node stroke width, in pixels
  nodeStrokeOpacity = 1, // node stroke opacity
  nodeRadius = 5, // node radius, in pixels
  nodeStrength,
  linkSource = ({source}) => source, // given d in links, returns a node identifier string
  linkTarget = ({target}) => target, // given d in links, returns a node identifier string
  linkStroke = "#999", // link stroke color
  linkStrokeOpacity = 0.6, // link stroke opacity
  linkStrokeWidth = 1.5, // given d in links, returns a stroke width in pixels
  linkStrokeLinecap = "round", // link stroke linecap
  linkStrength,
  colors = d3.schemeTableau10, // an array of color strings, for the node groups
  width = 640, // outer width, in pixels
  height = 400, // outer height, in pixels
  invalidation // when this promise resolves, stop the simulation
} = {}) {
  // Compute values.
  const N = d3.map(nodes, nodeId).map(intern);
  const R = typeof nodeRadius !== "function" ? null : d3.map(nodes, nodeRadius);
  const LS = d3.map(links, linkSource).map(intern);
  const LT = d3.map(links, linkTarget).map(intern);
  if (nodeTitle === undefined) nodeTitle = (_, i) => N[i];
  const T = nodeTitle == null ? null : d3.map(nodes, nodeTitle);
  const G = nodeGroup == null ? null : d3.map(nodes, nodeGroup).map(intern);
  const W = typeof linkStrokeWidth !== "function" ? null : d3.map(links, linkStrokeWidth);
  const L = typeof linkStroke !== "function" ? null : d3.map(links, linkStroke);
  

  // Replace the input nodes and links with mutable objects for the simulation.
  nodes = d3.map(nodes, (_, i) => ({id: N[i]}));
  links = d3.map(links, (_, i) => ({source: LS[i], target: LT[i]}));

  // Compute default domains.
  if (G && nodeGroups === undefined) nodeGroups = d3.sort(G);

  // Construct the scales.
  const color = nodeGroup == null ? null : d3.scaleOrdinal(nodeGroups, colors);

  // Construct the forces.
  const forceNode = d3.forceManyBody();
  const forceLink = d3.forceLink(links).id(({index: i}) => N[i]);
  if (nodeStrength !== undefined) forceNode.strength(nodeStrength);
  if (linkStrength !== undefined) forceLink.strength(linkStrength);

  const simulation = d3.forceSimulation(nodes)
      .force("link", forceLink)
      .force("charge", forceNode)
      .force("center",  d3.forceCenter())
      .on("tick", ticked);

  const svg = d3.create("svg")
      .attr("width", width)
      .attr("height", height)
      .attr("viewBox", [-width / 2, -height / 2, width, height])
      .attr("style", "max-width: 100%; height: auto; height: intrinsic;");

  const link = svg.append("g")
      .attr("stroke", typeof linkStroke !== "function" ? linkStroke : null)
      .attr("stroke-opacity", linkStrokeOpacity)
      .attr("stroke-width", typeof linkStrokeWidth !== "function" ? linkStrokeWidth : null)
      .attr("stroke-linecap", linkStrokeLinecap)
    .selectAll("line")
    .data(links)
    .join("line");

  const node = svg.append("g")
      .attr("fill", nodeFill)
      .attr("stroke", nodeStroke)
      .attr("stroke-opacity", nodeStrokeOpacity)
      .attr("stroke-width", nodeStrokeWidth)
    .selectAll("circle")
    .data(nodes)
    .join("circle")
      .attr("r", nodeRadius)
      .call(drag(simulation));

  if (W) link.attr("stroke-width", ({index: i}) => W[i]);
  if (L) link.attr("stroke", ({index: i}) => L[i]);
  if (G) node.attr("fill", ({index: i}) => color(G[i]));
  if (R) node.attr("r", ({index: i}) => R[i]);
  if (T) node.append("title").text(({index: i}) => T[i]);
  if (invalidation != null) invalidation.then(() => simulation.stop());

  function intern(value) {
    return value !== null && typeof value === "object" ? value.valueOf() : value;
  }

  function ticked() {
    link
      .attr("x1", d => d.source.x)
      .attr("y1", d => d.source.y)
      .attr("x2", d => d.target.x)
      .attr("y2", d => d.target.y);

    node
      .attr("cx", d => d.x)
      .attr("cy", d => d.y);
  }

  function drag(simulation) {    
    function dragstarted(event) {
      if (!event.active) simulation.alphaTarget(0.3).restart();
      event.subject.fx = event.subject.x;
      event.subject.fy = event.subject.y;
    }
    
    function dragged(event) {
      event.subject.fx = event.x;
      event.subject.fy = event.y;
    }
    
    function dragended(event) {
      if (!event.active) simulation.alphaTarget(0);
      event.subject.fx = null;
      event.subject.fy = null;
    }
    
    return d3.drag()
      .on("start", dragstarted)
      .on("drag", dragged)
      .on("end", dragended);
  }

  return Object.assign(svg.node(), {scales: {color}});
}
```

## 详细设计

### 1. 视觉风格设计 (Visual Style) - 性能优先的炫酷
目标是打造一个**深色、科技感、星系状**的知识图谱。

*   **主题色 (Theme)**：**深色宇宙 (Dark Cosmos)**。背景使用深灰/黑色 (`#1e1e1e` 或更深)，避免刺眼，突显节点亮度。
*   **节点渲染 (Nodes)**：
    *   **发光效果 (Glow)**：**[性能修正]** 严禁在渲染循环中使用 `ctx.shadowBlur`。
        *   **方案**：使用 **预渲染 Sprite (贴图)**。在内存 Canvas 中预先画好几种不同颜色/大小的“发光圆点”，渲染时直接使用 `drawImage` 复用这些贴图。
    *   **颜色编码**：
        *   **目录**：紫色/深蓝，代表“星系中心”。
        *   **Source文件**：青色 (Cyan)，代表逻辑。
        *   **Test文件**：绿色 (Green)，代表保障。
        *   **Config文件**：橙色 (Orange)，代表配置。
    *   **大小映射**：
        *   目录：固定较大半径，或根据包含文件数对数增长。
        *   文件：根据文件大小或 PageRank 值动态调整。
*   **连线渲染 (Links)**：
    *   **基础状态**：低透明度 (0.1-0.2) 的细线。
    *   **高亮状态**：高亮且发光，模拟“能量传输”。

### 2. 交互与动效设计 (Interaction & Animation)

#### 2.1 动态交互
*   **入场策略 (Loading Strategy)**：
    *   **默认折叠**：初始只展示 **Root 目录** 和 **一级子目录/文件**。
    *   **渐进式展开**：双击目录节点，展开/折叠其直接子节点。
    *   **布局更新**：展开时，新节点从父节点位置“生出”，力导向重新平衡；折叠时，子节点收缩回父节点。
*   **悬浮 (Hover) - 聚光灯效果**：
    *   鼠标悬浮节点时，**高亮**该节点及其直接依赖路径（上游和下游）。
    *   **压暗 (Dim)** 其他无关节点。
*   **点击 (Click) - 详情与定位**：
    *   点击节点：右侧滑出详情面板。
    *   双击文件节点：在 VSCode 编辑器中打开该文件。

#### 2.2 基础操作
*   **缩放/平移**：支持鼠标滚轮缩放和拖拽平移。
*   **搜索定位**：提供搜索框，输入文件名，视图自动飞向并高亮目标节点。

### 3. 性能优化方案 (Performance Optimization)

#### 3.1 计算优化 (Web Worker)
*   **独立线程**：`GraphWorker.ts` 负责 d3-force 的 simulation tick 计算。
*   **消息机制**：
    *   Main -> Worker: 发送全量 GraphData，或发送“展开/折叠”指令（更新 nodes/links 子集）。
    *   Worker -> Main: 每帧（或每N帧）发送计算后的节点坐标 `Float32Array`。

#### 3.2 渲染优化 (Rendering)
*   **离屏 Canvas**：静态背景、网格绘制在离屏 Canvas。
*   **视锥剔除 (Frustum Culling)**：只渲染 Viewport 内的节点。
*   **LOD (Level of Detail)**：
    *   Zoom < 0.5: 隐藏文字标签，只画点。
    *   Zoom < 0.2: 隐藏连线，只画大目录点。

### 5. 后端实现逻辑 (`src/core/knowledge-graph`)

VS Code 插件的 `vscode` API 原生支持创建多个独立 Webview 面板，满足「点击按钮打开新 Webview」的需求：
- **实现逻辑**：
  1. 在原有 React  Webview 的按钮点击事件中，通过 `vscode.window.createWebviewPanel` 创建新面板（指定独立 ID、标题、显示位置）；
  2. 新 Webview 可加载独立的 HTML/JS 资源（可复用插件的 React 环境，或直接使用纯 HTML+D3，推荐前者以保持技术栈统一）；
  3. 新 Webview 与原有 Webview 完全隔离，拥有独立的 DOM 上下文和通信通道，不会相互干扰。
- **关键 API 支持**：
  ```typescript
  // 插件后端（Node.js 侧）响应按钮事件，创建新 Webview
  vscode.commands.registerCommand('your-plugin.open-force-graph', () => {
    const panel = vscode.window.createWebviewPanel(
      'forceGraphWebview', // 唯一 ID
      '力导图可视化',       // 面板标题
      vscode.ViewColumn.Beside, // 显示在右侧编辑器
      { enableScripts: true } // 允许执行 JS（必须）
    );
    // 加载 Webview 内容（React 打包后的 HTML 或纯 HTML）
    panel.webview.html = getWebviewContent(panel.webview);
  });
  ```


### 2. React + D3.js 集成：成熟方案
原有插件基于 React 框架，新 Webview 可直接复用 React 环境，通过「React 管理状态 + D3 处理可视化渲染」的模式集成，无技术冲突：
- **集成方式**：
  1. React 负责接收数据、管理 Webview 生命周期（如初始化、销毁）；
  2. 通过 `useRef` 获取 Canvas/SVG 容器 DOM，在 `useEffect` 中初始化 D3 力导模拟；
  3. 数据更新时，通过 React 状态触发 D3 模拟的重新计算或节点更新。
- **核心代码示例（React 组件内）**：
  ```jsx
  import { useRef, useEffect, useState } from 'react';
  import * as d3 from 'd3';

  const ForceGraph = ({ initialData }) => {
    const canvasRef = useRef(null);
    const [graphData, setGraphData] = useState(initialData);

    useEffect(() => {
      const canvas = canvasRef.current;
      const ctx = canvas.getContext('2d');
      const width = canvas.clientWidth;
      const height = canvas.clientHeight;

      // 1. 初始化 D3 力导模拟（关键优化：用 Canvas 而非 SVG）
      const simulation = d3.forceSimulation(graphData.nodes)
        .force('link', d3.forceLink(graphData.links).id(d => d.id).distance(30))
        .force('charge', d3.forceManyBody().strength(-50)) // 斥力调整
        .force('center', d3.forceCenter(width / 2, height / 2))
        .alphaTarget(0.3); // 减少迭代次数，提升性能

      // 2. Canvas 渲染函数
      const render = () => {
        ctx.clearRect(0, 0, width, height);
        // 绘制链接
        ctx.beginPath();
        graphData.links.forEach(link => {
          ctx.moveTo(link.source.x, link.source.y);
          ctx.lineTo(link.target.x, link.target.y);
        });
        ctx.strokeStyle = '#999';
        ctx.stroke();
        // 绘制节点
        graphData.nodes.forEach(node => {
          ctx.beginPath();
          ctx.arc(node.x, node.y, 2, 0, 2 * Math.PI);
          ctx.fillStyle = '#666';
          ctx.fill();
        });
      };

      // 3. 模拟更新时触发渲染
      simulation.on('tick', render);

      // 4. 数据变化时更新模拟
      return () => simulation.stop(); // 组件卸载时停止模拟，避免内存泄漏
    }, [graphData]);

    // 接收插件端的实时数据更新（通过 postMessage）
    useEffect(() => {
      const handleMessage = (event) => {
        if (event.data.type === 'graphDataUpdate') {
          setGraphData(event.data.payload);
        }
      };
      window.addEventListener('message', handleMessage);
      return () => window.removeEventListener('message', handleMessage);
    }, []);

    return <canvas ref={canvasRef} style={{ width: '100%', height: '100vh' }} />;
  };
  ```


### 3. 10万节点性能支撑：优化后可行
D3 力导模拟的核心性能瓶颈是「计算复杂度」和「渲染开销」，10万节点属于大规模数据，但通过以下优化可实现流畅运行：

| 性能瓶颈                | 解决方案                                                                 |
|-------------------------|--------------------------------------------------------------------------|
| 渲染开销（DOM 爆炸）    | 用 **Canvas 替代 SVG**：SVG 每个节点是独立 DOM 元素，10万节点会导致重排重绘崩溃；Canvas 是位图批量渲染，性能提升 10-100 倍 |
| 力导计算阻塞主线程      | 用 **Web Worker 分流计算**：将 D3 模拟的力计算逻辑移到 Web Worker，主线程仅负责渲染，避免 UI 卡顿 |
| 全量数据传输延迟        | 1. 增量更新：仅传输变化的节点/链接（新增/删除/位置变更），而非全量数据；2. 数据压缩：用 MessagePack 替代 JSON（体积减少 50%+） |
| 模拟迭代耗时            | 优化 D3 力导参数：<br>- 降低 `alphaTarget`（如 0.2-0.3）减少迭代次数；<br>- 限制 `forceManyBody.distanceMax`（如 100）减少计算量；<br>- 关闭不必要的力（如无链接时禁用 `forceLink`） |
| 内存占用过高            | 1. 节点复用：避免频繁创建新节点对象，更新已有节点的位置/属性；<br>2. 生命周期管理：关闭 Webview 时销毁模拟、Web Worker、数据引用 |

- **实测参考**：Canvas + Web Worker 优化后，10万节点的力导模拟可稳定在 30+ FPS，节点移动流畅，无明显卡顿。


### 4. 实时数据同步：技术成熟
数据流向：`插件后端 → 新 Webview → D3 模拟`，全链路实时性可通过以下方案保障：
- **1. 插件后端 ↔ 新 Webview 通信**：
  利用 VS Code Webview 原生的 `postMessage` 机制（双向通信），支持 JSON/二进制数据传输：
  - 插件端发送数据：`panel.webview.postMessage({ type: 'graphDataUpdate', payload: updatedData })`；
  - Webview 接收数据：通过 `window.addEventListener('message', handleMessage)` 监听，如上述 React 组件示例。
- **2. 插件后端 ↔ 原有后端数据同步**：
  - 若原有后端支持 WebSocket（推荐）：插件后端建立 WebSocket 连接，实时接收数据变化推送，无需轮询；
  - 若无 WebSocket：用「长轮询」或「SSE（服务器推送事件）」替代，延迟可控制在 100ms 内，满足实时性需求。


### 5. 资源加载与兼容性：无阻碍
- **D3.js 引入**：可通过 CDN（如 `https://d3js.org/d3.v7.min.js`）或插件本地资源（通过 `webview.asWebviewUri` 转换路径）加载，无跨域问题（VS Code Webview 有独立 Origin）；
- **兼容性**：VS Code Webview 基于 Chromium 内核，对 Canvas、Web Worker、D3.js 均完美支持，无需兼容低版本浏览器；
- **生命周期管理**：新 Webview 面板关闭时，通过 `panel.onDidDispose` 事件停止模拟、销毁 Web Worker、取消数据监听，避免内存泄漏。


## 二、风险点与应对方案
| 潜在风险                | 应对方案                                                                 |
|-------------------------|--------------------------------------------------------------------------|
| 10万节点全量数据传输耗时 | 1. 增量更新：仅传输变化数据（如 `{ addedNodes: [], removedNodeIds: [], updatedNodes: [] }`）；<br>2. 二进制压缩：用 `msgpack-lite` 压缩数据，传输效率提升 2-3 倍 |
| Web Worker 数据拷贝开销 | 用 `Transferable Objects` 传输二进制数据（如 `Uint8Array`），避免数据深拷贝 |
| 力导模拟不稳定（节点抖动） | 调整 `damping`（阻尼系数，如 0.95）和 `alphaDecay`（衰减系数），让模拟快速稳定 |
| 内存泄漏                | 1. 关闭 Webview 时销毁 D3 模拟、Web Worker、WebSocket 连接；<br>2. 避免全局变量引用大体积数据 |
